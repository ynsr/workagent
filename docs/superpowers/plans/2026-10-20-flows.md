# Flows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement flow chaining (Start → … → Cleanup → Release) per the approved design.

**Architecture:** Approach A — `cli_flow.py` orchestrates by dispatching each step to its existing runner in-process with merged flags; store layer mirrors `store_custom_actions.py`; web mirrors via `web_args.py` SPECS; one shared `ChainEditor` serves both template-edit and run-launch wizard modes.

**Tech Stack:** Python (Typer CLI, stdlib sqlite3, no ORM), FastAPI serve passthrough (`python -m workagent` children), React + TS frontend (Vite build, `tsc -b`).

**Spec:** `docs/superpowers/specs/2026-10-20-flows-design.md`

## Global Constraints

- stdout carries ONLY data; every log/progress/confirmation line → stderr.
- Exit codes: `0` success, `1` general error, `2` usage/needs-human-input.
- Python files and React components/classes must not exceed 500 lines.
- Parity checklist per feature: CLI flag → web arg passthrough → API_CONTRACT.md entry → frontend control → both test files (`tests/test_cli.py` + `tests/test_webapp.py` style coverage) in the same PR.
- Timestamp columns render human-readable relative time with exact date as hover tooltip; uniform across all tabs.
- No component may block rendering on data loading (stale-while-revalidate, never blank/blocked render).
- CHANGELOG.md entries <= 150 chars, append issue ID in brackets; gap insert only (`PUT >N:`), verify `git diff` shows additions only.
- The AI runtime component is named `harness` everywhere; old `runtime` spelling must not be reintroduced.
- Merges from feature branches into destination use squash (cleanup path); default→release merges are fast-forward only via MR auto-merge; sync local merge never squashes.
- The keyword is `Release`, never `Deploy`.
- Bulk operations skip deactivated worktrees and operate only on active ones.
- Direct `sed`/`perl`/`python` edits via bash are forbidden; use the edit tool for surgical patches.

## Review Focus

- `flow run` on a template whose custom-action label was deleted after save must fail fast before step 0 with exit 2 naming the label, never mid-chain.
- Re-running a `failed` flow must resume after the last green step, never replay green steps.
- A `paused` (preview/terminal) flow re-run must continue the chain, never report failure.
- Two flows on same-repo worktrees with Release steps must ship once; the loser records `skipped:release-locked`, never a duplicate MR or a failure.
- `GET /api/flows` must hide flows whose worktree is soft-deleted, and `link undelete` must restore them.

`validate_template(steps, get_action=None) -> list[dict]`: accept a list of step dicts (or a JSON string — parse it); raise `HarnessError(msg, exit_code=2)` on: empty chain; unknown `kind`; `start` present but not first; `start` duplicated; `release` present but not last; `release` without a prior `cleanup`; any `review`…`cleanup` span lacking `fix_comments` between them; `action` step outside `(start, cleanup)` bounds (i.e. before start or at/after cleanup); `action` step missing `action_label`; `action_label` failing `validate_label`; when `get_action` is supplied, unknown `action_label`; step `config` containing `then-fix-comments`/`then_fix_comments` keys or string values; `cleanup` step `config` containing `hard_delete`/`hard-delete`/`no_squash`/`no-squash`. Return the normalized list (each step `{"kind": k, "action_label": ..., "config": {...}}` with `config` default `{}`).

CRUD mirrors `store_custom_actions` exactly: `create_template` requires non-blank `name`, label defaults to `normalize_label(name)`, validates steps via `validate_template`, stores `steps` as JSON text; `update_template` allows `{name, steps, pre_execution, post_execution}` (label immutable — not in allowed set), re-validates `steps` when present; `delete_template` raises exit 2 on unknown label.

Flow rows: `create_flow(db, *, template_label, worktree_ref="", repo_snapshot=None)` inserts `status="pending"`, `current_step=0`, `step_results="[]"`; `get_flow(db, flow_id)` returns parsed row or None; `list_flows(db, worktree="", include_deleted_worktrees=False)` joins `worktrees w ON w.ref_key = flows.worktree_ref` and, unless `include_deleted_worktrees`, filters `(w.deleted_at IS NULL OR w.deleted_at = '')` — same predicate as `store_links.load_links_rows`; flows with empty `worktree_ref` (pre-Start issue flows) are always listed. `update_flow(db, flow_id, **fields)` allows `{worktree_ref, repo_snapshot, status, current_step, step_results}` (dict/list values JSON-encoded), validates `status ∈ FLOW_STATUSES`, bumps `modified_at`, raises exit 2 on unknown id.

Create `src/workagent/cli_flow.py` with `flow_app = typer.Typer(...)` + `template_app` subgroup (`app.add_typer(flow_app, name="flow")`, `flow_app.add_typer(template_app, name="template")`). Template CRUD mirrors `cli_action.py` (`template add --name [--label] [--steps JSON] [--pre-execution] [--post-execution] [--json]`, `list`, `show`, `update`, `delete`). `--steps` accepts a JSON list of step dicts (validated via `validate_template`); omit → template with empty steps is rejected (non-empty rule) — the wizard builds steps, CLI requires them.

`flow run <template> <ref> [--step-config JSON] [--dry-run] [--yes] [--json]`:

```python
tpl = store.get_template(template)
if tpl is None:
    _fail(f"unknown flow template: {template!r}", EXIT_USAGE)
steps = sf.validate_template(tpl["steps"], get_action=store.get_action)  # fail fast pre-step-0
overrides = json.loads(step_config or "{}")  # must be a dict, else exit 2
```

`--dry-run` prints `{"template": label, "ref": ref, "chain": merged_steps}` and returns (no flow row created). Otherwise `create_flow(template_label=label)` → resolve ref (worktree adopt vs issue Start — delegate the actual Start execution to the step loop, but pre-resolve the key for the row when it is a worktree via `worktrees.resolve_any`; issue refs leave `worktree_ref=""` until step 0 completes) → run template `pre_execution` via `release_gates.run_repo_command` when a worktree exists (no worktree yet for issue flows: skip pre until step 0 lands, then run it — document this ordering) → loop `steps[current_step:]` dispatching per kind:

- `start`: call the existing start runner in-process for the ref (adopt when the worktree already exists); after success, `update_flow(worktree_ref=key, repo_snapshot={repo, default_branch, release_branch})`.
- `review`/`fix_comments`/`sync`: call existing runners with merged flags; each mints session/run rows with `flow_id` in session metadata (pass through the metadata seam each runner already supports; if a runner lacks it, wrap: `set_session_metadata(sid, {"flow_id": fid})` after the call — verify per runner while implementing).
- `action`: `store.get_action(action_label)` (re-validate live; deleted → fail fast is already done up front, but re-check here for races) then the `action run` path in-process.
- `cleanup`: fixed flags (squash + soft-delete; reject overrides containing hard-delete/no-squash with exit 2). After success the worktree row is soft-deleted — later steps must not touch links.
- `release`: read `repo_snapshot` from the flow row (never links); acquire the per-repo release lock; on lock contention record `skipped:release-locked` in step results and finish `done` (not failure).

After each step, persist `current_step` + append `{kind, status: ok|failed|skipped, detail}` to `step_results`. Step failure → `status=failed`, exit 1. Preview/terminal step outcome → `status=paused`, print the manual command to stderr, exit 0 (re-run resumes). All green + `post_execution` ok → `status=done`. Post-fail → `status=failed`, exit 1.

Resume: `flow run` on a template+ref that already has a non-done flow row reuses it (latest for the pair) starting at `current_step`; add `--fresh` to force a new flow row. (Without this, "resume from failed step" has no handle.)

`flow list [--worktree REF] [--json/--csv]`, `flow show <id> [--json]` (steps + per-step results + repo snapshot).

Register in `cli.py`: `from . import cli_flow  # noqa: F401 (register flow commands)`.
